# B：面向非专业创作者的照片式交互导览低代码制作

状态：候选。

目标用户：讲解员、学生、展览组织者；是否真实需要自行制作，待访谈确认。
方案：导入地图和照片 → 标注区域 → 连接场景 → 配置知识卡与探索任务 → 预览导览。

研究问题：哪些编辑表达和错误提示能降低新手理解空间关系与任务逻辑的成本？
实现范围：重新设计场景编辑、任务配置和播放端；技术栈待定。循迹中都仅作为最终体验的效果参考。
开发内容：定义项目数据结构，建立完整的制作、预览流程。

验证：通过竞品调研确定对照工具或人工制作流程，在同等培训条件下完成同一任务；记录成功率、耗时、错误、求助及主观易用性。采用任务顺序平衡，降低学习效应。
风险：只有表单与拖拽功能，可能不足以形成研究贡献。应选定可测的交互改进。
首个小样：通过新工具配置一个含 3—5 个地点的虚拟导览，再用另一组场景检验通用性。
工作量判断：需覆盖编辑与播放两端，开发成本应在可行性调研中单独估算。

## 需求分析

- 目标用户：讲解员、学生、展览组织者；“他们是否愿意且被允许自行制作导览”是本方向的首要假设，需访谈确认。
- 现有证据：终端用户开发系统综述表明非程序员制作数字内容是成熟领域，但工具好坏须用真实任务评价（B 组论文 1）；XR 文化遗产创作工具研究发现新手与熟练用户需求差异显著（论文 2），“无代码”不自动等于好用（论文 3）。
- 竞品现状：720 云等 SaaS 面向商业摄影与营销客户，Pano2VR、krpano 面向专业人员且授权约 €179—499（见[竞品对比](../../02-案例与参考/论文与竞品/竞品调研/竞品对比.md)）。
- 待验证：让目标用户用现有工具完成一次小样，记录卡点，再确定本工具要改进的具体环节。

## 候选创新点

1. **空间关系直接操纵**：在平面图上直接连接场景并即时显示连通状态，与表单式、列表式编辑做对照。
2. **错误前置预防**：对断连、孤儿场景、任务死锁在编辑时即提示，比较其相对“事后报错”对新手错误率的影响。
3. **新手模式与高级模式分层**（论文 2 支持其合理性），分别评价上手时间与表达能力。

边界：拖拽、表单与可视化编辑本身已不是创新；研究贡献必须收敛到一个可测的交互改进。

## 实现难度：中高

| 模块 | 难度 | 说明 |
| --- | --- | --- |
| 项目数据结构 | 中 | 与播放端共用，需先定 schema |
| 场景与任务编辑器 | 高 | 工作量主体，交互形式需多轮迭代 |
| 预览与播放端 | 中 | 需与编辑器数据实时一致 |
| 用户实验 | 中高 | 招募、培训平衡、指标记录均需设计 |

最小小样：只做“连接场景 + 配置一类探索任务 + 预览播放”闭环，组织 6—8 名目标用户做小样本任务测试，记录成功率、耗时、错误与求助次数，再决定是否扩展功能。
