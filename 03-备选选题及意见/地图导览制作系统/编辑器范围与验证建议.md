# B 方向意见：先验证照片式导览编辑器的制作成本与迁移边界

- 日期：2026-09-29
- 选题编号与版本：B，[当前选题说明](选题说明.md)（2026-09-28 阅读版本）
- 提出人及角色：Nyasd，团队成员
- 意见性质：个人建议，供讨论，不代表团队定题
- 结论：继续调研；确认真实制作需求后，再决定是否开展小样。

## 支持点及依据

我认为这个方向值得继续调研，但“给任意景点填入资料，就能生成探索小程序”的范围过大。应先问清楚：哪些内容可以直接替换，哪些交互仍需要程序员介入？如果换一个场景就要改播放端逻辑，编辑器降低制作成本的价值就还没有得到证明。

可以把首批目标用户收窄为有图文资料、需要制作小型线上导览的学生或展览组织者。这个群体是否愿意自己制作、当前卡在哪一步，仍需访谈，不能由开发者代替他们回答。[循迹中都](../../02-案例与参考/效果参考/循迹中都.md)可帮助讨论最终体验；新系统按仓库约定独立设计与开发，不复用其代码、素材或工程实现。

## 反对点及竞品依据

以下仅核对官方页面和文档，未完成注册试用或制作耗时测评。“文档未说明”不等于产品没有该能力。

| 参考工具 | 官方资料能够确认的功能 | 对选题的判断及待核实处 |
| --- | --- | --- |
| H5P Virtual Tour (360) [1] | 普通图片和全景图片可加入图文、音视频、问题，并连接其他场景 | “照片＋热点＋场景跳转”已有现成实现，不能单独当作创新点。应实测同类制作任务，核对任务依赖表达和错误反馈是否符合需求 |
| Actionbound [2] | 在浏览器制作、在移动 App 体验；支持问答、任务、GPS、地图和二维码等元素 | “导览＋探索任务”已有产品。它偏现实场所的互动活动，可借鉴任务编辑；照片式虚拟探索与实地 GPS 导览的操作不同，不宜直接比较完整流程耗时 |
| Twine [3] | 用带箭头连线展示段落链接；重命名段落时可更新常规链接，但不覆盖所有依赖具体故事格式的代码引用 | 可以借鉴关系可视化与引用维护。图形连线本身不是新贡献，也不能据此断言它能检查本项目的空间或任务规则 |

我的判断是：单做一个表单和拖拽工具，研究贡献可能不足。建议聚焦一个可检验的问题：**相比只有场景列表和表单的编辑方式，把场景连接与任务前置关系放在同一视图中，能否帮助新手更快发现并修复配置错误？** 这是待验证假设，尚未证明优于现有工具。

## 建议缩减范围

首个小样只支持普通照片上的热点探索：地图选点 → 照片场景 → 查看知识卡或完成固定任务 → 预览。先暂缓角色自由行走、透视缩放和前景遮挡；它们需要额外区域标注和素材处理，应另行计算制作成本，不能都算作“填资料”。

| 第一版允许配置 | 建议边界 |
| --- | --- |
| 地点、照片与地图位置 | 稳定编号、名称、图片、示意图坐标；不承担现实道路导航 |
| 热点、知识卡和来源 | 点击区域、文本、图片、资料出处与素材授权记录 |
| 场景连接 | 起点、终点及跳转入口；删除目标时提示受影响的连接 |
| 任务与前置条件 | 先限制为查看、收集、单选三类；任务前置关系先限定为无环依赖 |
| 预览与导出 | 用同一个播放端读取配置，先以网页预览验证；微信端发布另作适配评估 |

示例：制作“先阅读展板，再找到照片中的纹样，最后回答一道问题”的流程。场景跳转允许返回，因此不能把所有场景环路都判错；只有已约定为无环的任务前置关系出现循环时才提示错误。

第二组内容优先选择容易取得授权的小型校园展览或校园导览。通过修改照片、热点、知识卡、连接和任务完成迁移；记录所有不得不改代码或临时增加字段的情况。两个场景通过也只能支持这一类任务的可配置性，不能推出适用于任意景点。

## 必须验证的问题与下一步

以下为拟开展工作，尚未执行；负责人由团队认领后补充。

1. **需求是否存在。** 先访谈 3—5 位潜在制作者，了解最近一次制作经历、更新频率、现有工具和困难；争取至少一份可授权使用的真实内容。不能只问“你喜不喜欢这个想法”。
2. **现成工具是否已足够。** 沿用[竞品调研清单](../../02-案例与参考/论文与竞品/调研清单.md)的统一任务：5 个地点、2 条路线、3 个交互任务、1 处无效连接。优先用 H5P 实作可比部分，记录版本、配置步骤、发布条件和无法表达的需求；不可比部分单列，不能把缺少功能直接算成操作失败。
3. **哪种交互真正减少错误。** 若进入小样阶段，在同一播放端、数据和检查规则下，对比“列表＋表单”和“关系视图＋表单”，只改变关系呈现方式。安排两组难度相近的素材并平衡操作顺序，使用相同培训，记录完成率、修复时间、残留错误和求助次数。无效连接作为基本修复题，任务前置循环作为另一个独立题；限时未完成单独报告。先做少量试测调整任务，不把试测当成统计结论。
4. **迁移成本在哪里。** 分开记录资料搜集、素材处理、标注、任务配置、修错与发布耗时，避免只报告编辑器内操作时间。第二场景要求不改播放端代码；若失败，记录原因并收窄支持范围。

建议的判断门槛：如果现成工具已满足真实任务且没有明显痛点，暂缓独立开发；若需求明确，再围绕一个编辑难点做小样。若关系视图没有带来可解释的改善，也应保留负结果，重新讨论 B 方向，不预设必须把 A、C、D 等方向一并做进去。
